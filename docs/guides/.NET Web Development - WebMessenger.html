2. Create a Basic ASP.NET Core Application

What is already in this project

  • Web entry point and pipeline in Program.cs
  • Dependency Injection registration for app services and infrastructure

3. Configure an Application

Current configuration model in WebMessenger

  1. appsettings.json - base defaults (Serilog, JWT, Dropbox keys placeholders)
  2. appsettings.Development.json - dev log level overrides
  3. appsettings.Production.json - production overrides
  4. User secrets enabled via <UserSecretsId>webmessenger-api-secrets</UserSecretsId>
  5. Environment variables override all previous sources at runtime
  6. Strongly typed options are bound and validated on startup via IOptions<T>
// Program.cs configuration examples
builder.Configuration.GetConnectionString("DefaultConnection")

builder.Services
    .AddOptions<JwtOptions>()
    .BindConfiguration(JwtOptions.SectionName)
    .ValidateDataAnnotations()
    .ValidateOnStart();

builder.Services
    .AddOptions<DropboxOptions>()
    .BindConfiguration(DropboxOptions.SectionName)
    .ValidateDataAnnotations()
    .ValidateOnStart();

IOptions<T> status in this repo

AuthService now consumes IOptions<JwtOptions>, and DropboxFileStorage consumes IOptions<DropboxOptions>. This makes configuration strongly typed and validated at startup.
Practical speaking point: this repository demonstrates both configuration precedence and production-friendly options validation in one setup.

5. Configure and Work with an ORM (EF Core)

What is implemented

  • ApplicationDbContext with DbSets: Users, Chats, Messages, ChatMembers, Contacts
  • Entity relationships and constraints in OnModelCreating
  • Indexes for common access paths (username, message timeline, contact uniqueness, online flag)
  • Migrations committed in WebMessenger.DAL/Migrations
  • CRUD via repository + Unit of Work abstraction
// Examples from ApplicationDbContext
entity.HasIndex(u => u.Username).IsUnique();
entity.HasIndex(m => new { m.ChatId, m.SentAt });
entity.HasIndex(c => new { c.OwnerUserId, c.ContactUserId }).IsUnique();

entity.HasOne(c => c.OwnerUser)
      .WithMany(u => u.Contacts)
      .HasForeignKey(c => c.OwnerUserId)
      .OnDelete(DeleteBehavior.Restrict);

CRUD, pagination and filtering in services

  • Create: InsertAsync, CreateRangeAsync (users, chat members, messages)
  • Read/filter: LINQ with Where, OrderBy, Take, AnyAsync
  • Pagination style: cursor-like before + limit in chat/message endpoints
  • Update: UpdateAsync + CommitAsync

Migrations in runtime pipeline

// Program.cs startup migration step
db.Database.Migrate();
Log.Information("Database migration completed");

6. Validate Input Data (Data Annotations)

Current validation approach in this repo

  • DTO-level DataAnnotations in WebMessenger.Contracts/Models:
    • LoginDto: [Required], [MaxLength]
    • RegisterDto: [Required], [MinLength], [MaxLength]
    • UpdateProfileDto: [EmailAddress], [Phone], [Url], [MaxLength]
    • SendMessageRequest, AddContactRequest: [Required], [MaxLength]
  • Entity-level DataAnnotations in WebMessenger.DAL/Entities:
    • User: [Required], [EmailAddress], [Phone], [Url], [MaxLength]
    • Chat, Message, Contact: key string constraints and required content
  • Manual guards in controllers/services remain for business rules:
    • empty query check in UserController.Index
    • avatar MIME/size checks in UserController.UploadAvatar
    • self-contact prevention in ContactsService.AddContactAsync
    • empty message guard in ChatService.SendMessageToUserAsync
Because controllers use [ApiController], invalid annotated request models are automatically rejected with 400 responses before action logic runs.

7. Handle Errors (ProblemDetails + Middleware)

Existing global setup

builder.Services.AddProblemDetails(options =>
{
    options.CustomizeProblemDetails = context =>
    {
        context.ProblemDetails.Extensions["traceId"] = context.HttpContext.TraceIdentifier;
    };
});

app.UseExceptionHandler();

Controller-level handling pattern

  • Expected domain exceptions are mapped to 400/404/403
  • Unexpected exceptions are logged and returned as 500
  • Consistent try/catch + ILogger style across major controllers
This is a valid baseline for production APIs: centralized exception handler + contextual controller logs.

9. Basic Authentication and Authorization

What is implemented

  • JWT Bearer authentication in Program.cs
  • Token issuance in AuthService.GenerateJwtToken
  • Protected endpoints via [Authorize]
  • SignalR token extraction for /hubs/chat from query/cookie
  • Current user resolution from claims via CurrentUser
// JWT claim examples in AuthService
new Claim(JwtRegisteredClaimNames.Sub, user.Id.ToString()),
new Claim(JwtRegisteredClaimNames.UniqueName, user.Username),
new Claim(ClaimTypes.NameIdentifier, user.Id.ToString())
Role-based authorization is not configured yet (no explicit role claims or role policies in current API).

10. Asynchronous Programming Practices

Current async usage

  • Async all the way through controllers, services, repository and UoW
  • EF Core async operators: ToListAsync, AnyAsync, FirstOrDefaultAsync, CountAsync
  • CancellationToken passed in message and read-receipt flows
  • SignalR events support optional CancellationToken
// Controller examples
public async Task<ActionResult<SendMessageResponse>> SendMessage(..., CancellationToken ct)
public async Task<IActionResult> MarkRead(..., CancellationToken ct)

// Service and DAL examples
await _uow.MessageRepository.InsertAsync(message, ct);
await _uow.CommitAsync(ct);
await _context.SaveChangesAsync(ct);
Small note: startup migration retry loop currently uses Thread.Sleep. It works, but async delay would be more scalable under heavy startup orchestration.

12. Integrate with External Services (HTTP/SDK)

Implemented integration: Dropbox SDK

  • Package: Dropbox.Api in API project
  • Adapter: DropboxFileStorage : IFileStorage
  • Operations: upload, delete, create/get shared link, direct link conversion
  • Failure handling: catch exceptions, log with context, return null/false
// construction from strongly typed options
public DropboxFileStorage(IOptions<DropboxOptions> dropboxOptions, ILogger<DropboxFileStorage> logger)
{
  _client = new DropboxClient(dropboxOptions.Value.AccessToken);
  _logger = logger;
}

// upload flow
await _client.Files.UploadAsync(path, WriteMode.Overwrite.Instance, body: fileStream);
var link = await GetOrCreateSharedLink(path);
return ConvertToDirectLink(link.Url);
Current repository does not yet register typed HTTP clients via IHttpClientFactory and has no explicit retry/timeout policies for generic outbound REST clients.
For this project, SDK-based integration is the real implemented case and is fully valid as an external integration example.
